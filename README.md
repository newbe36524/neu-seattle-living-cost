# neu-seattle-living-cost

A Seattle cost-of-living reference for students at the Northeastern University (NEU) Seattle campus.
The data and notes currently come from the repository author's personal experience; other students' data may be added later.

The site is built with [Astro](https://astro.build) and published through GitHub Pages:
<https://newbe36524.github.io/neu-seattle-living-cost/>

## Structure

```
src/
  data/categories.yaml # Cost item definitions (categories, items, periods), not tied to any one person
  data/profiles/*.yaml # One file per contributor: amount records that only reference item ids
  data/costs.ts        # Types, loading and build-time validation (no data)
  locales/<language>/  # Site copy: common.yml (shared), pages.yml (pages), data.yml (text for cost items and contributors)
  i18n/index.ts        # Runtime loading: language list, t(), path generation
  layouts/             # Page layouts (including the language switcher and hreflang)
  components/          # Home-page ledger and other components, plus page content under components/pages/
  pages/index.astro    # Root path: HagiLight default-language transit page that redirects to /en-US/
  pages/[lang]/        # Routes for index / costs / about; each language lives under /<language>/
  styles/global.css    # Base styles (including dark mode)
.github/workflows/deploy.yml   # Publishes Pages automatically on every push to main
```

## Local development

```bash
pnpm install
pnpm run dev      # http://localhost:4321/neu-seattle-living-cost/
pnpm run build    # Type check + build into dist/
pnpm run i18n:check   # Multilingual audit (@hagicode/hagi18n); runs before the build in CI
```

## Filling in data

Data is YAML under `src/data/`:

- `categories.yaml` defines the cost items (independent of any person). Add new items or categories here.
- `profiles/*.yaml` holds contributors' records, **one file per contributor**. To add a new student, add a new `.yaml` file in `profiles/`
  (copy `author-downtown.yaml` as a template; the field descriptions are in the file header). Leave out items they did not provide; the page automatically shows "To be added".
- If a contributor only gives a total, use a single record that covers several `items` (a merged entry); the amount is counted once.
- Numbers derived from reference prices get `basis: estimate`; the page labels them "Estimate" and counts them separately from reported amounts.
- Wrong fields, references to nonexistent items, duplicate records, and missing copy in the baseline language all make `pnpm run build` fail, with the file and the reason.

## Submitting data

The "Submit my data" button on the home page links to a GitHub issue form
(`.github/ISSUE_TEMPLATE/submit-data.yml`). Each amount field in the form corresponds to one cost item in `categories.yaml`.

- The form is generated by `scripts/gen-issue-template.mjs` from `categories.yaml` and the `en-US` `data.yml`. It is English only and **must not be edited by hand**.
  After adding or renaming a cost item, run `pnpm run issue-template` and commit the result; in CI, `pnpm run issue-template -- --check` fails when the form is out of date.
- When an issue with the `data-submission` label arrives, a maintainer reviews it, then adds `profiles/<id>.yaml` and the `profiles.<id>` copy in each language's `data.yml`, following the "Filling in data" section.
  Items left blank are not written; merged entries and estimates are handled according to the "Notes" and "Source of numbers" fields in the issue.
- Before first use, create a `data-submission` label in the repository (without it the template still works, but the label is not applied automatically).

## Commute time and contributor advice

Besides amounts, each contributor record can carry a few optional non-monetary fields (see the comments at the top of `profiles/*.yaml`):

- `housingType`: housing type, one of `apartment`, `studio`, `shared` (shared housing), `house` (detached or townhouse), `dorm` (student dorm). Shown as a badge with an icon; the names live under `housing.type.<id>` in each language's `common.yml`. When adding a type, also update `HOUSING_TYPES` in `src/data/costs.ts`, the icon in `Glyph.astro`, the copy in every language, and the dropdown options in `scripts/gen-issue-template.mjs`.
- `commute`: one-way commute from home to campus, split into legs in travel order, each leg `{ mode, minutes }`, where `mode` is `drive`, `transit` (public transit), `ferry`, or `walk`; the total minutes are the sum of the legs. The page draws it as a route "home → legs → campus", with a different animation rhythm for each mode. Time is also a cost, but not in dollars, so the page shows it separately and it is **not included in any dollar total**; when not provided it shows "To be added".
- `advice`: the contributor's own subjective advice, each entry `{ kind, id }`, where `kind` is `positive`, `negative`, or `neutral`;
  the title (a one-sentence summary) and body go in each language's `data.yml` under `profiles.<id>.advice.<id>.title` / `.text`. The page shows them in the order positive, negative, neutral, and hides the block when there is no advice. The section sits after the home-page totals and before the commute and per-category details, with the positive and negative groups side by side (each with a count).

In the submission form this corresponds to a "Housing type" dropdown, four minute inputs split by commute mode (walk / transit / ferry / drive, with the travel order written in the notes), and three "Advice" text boxes (one per line); maintainers split these into `advice` entries when processing the submission.

## Multilingual support

The site offers all 10 languages supported by HagiLight: `en-US` (the default display language), `zh-CN`, `zh-Hant`, `ja-JP`, `ko-KR`,
`de-DE`, `fr-FR`, `es-ES`, `pt-BR`, `ru-RU`. Pages live under `/<language>/`, for example `/en-US/about/`. The root path `/` is HagiLight's default-language transit page (`RootTransit`), which redirects to `/en-US/` after a moment and lists links to the other languages.

- Copy lives only in `src/locales/<language>/*.yml`, referenced as `filename.key.path` (for example `common.nav.home`). **Simplified Chinese is the baseline language**.
- `hagi18n.yaml` configures [`@hagicode/hagi18n`](https://www.npmjs.com/package/@hagicode/hagi18n): `pnpm run i18n:check`
  audits missing files, missing keys, extra keys, inconsistent `{{x}}` placeholders, and values identical to the baseline (suspected untranslated text); values that are intentionally identical are listed in `auditIdenticalAllowlist`.
- Adding copy: write `zh-CN` first, run `pnpm run i18n:sync` to preview and `pnpm run i18n:sync -- --write` to add the new keys to the other languages, then translate them one by one.
- Adding a cost item, category or contributor: the data YAML holds only ids, periods and amounts; names, descriptions and notes go in each language's `data.yml`
  (`items.<id>.label|hint`, `categories.<id>.title|description`, `profiles.<id>.contributor|area|summary|notes`).
  The key for a note is the first item id in that record's `items`; an estimate record without a note shows the generic estimate explanation.
- Amounts are always shown in US dollars with `en-US` formatting, regardless of language.
- Adding a language: add one entry each to the language lists in `src/i18n/index.ts` and `astro.config.mjs`, and create the three files under `src/locales/<language>/`.

## Deployment

In the repository Settings → Pages, set Source to **GitHub Actions**; after that every push to `main` deploys automatically.
